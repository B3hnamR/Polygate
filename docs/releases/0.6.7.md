## Polygate 0.6.7

OpenCode Free works again, including tool calls. This release also hardens updates on Windows and Linux, fixes dashboard totals after upgrading, and closes routing, Agent and Playground gaps. Updating is recommended, especially if OpenCode Free stopped answering after 0.6.6.

### OpenCode Free

- **Plain answers and tool calls work again.** 0.6.6 added stricter checks on OpenCode Free's streamed answers, and two normal OpenCode answers tripped them: a final chunk that repeats the finished answer beside the token usage (shown as "Upstream sent choice data after its terminal event"), and `"tool_calls": null` on every chunk of an answer (shown as a 502 "Upstream returned a tool call not permitted by the client's offered tools", #2). Both are accepted again. Thanks to @mdferin for reporting the tool-call failure (#2), and to @mahyartdb for digging into the OpenCode tool profile (#3). New text after an answer has finished, and tools the client did not offer, are still refused.
- **OpenCode 2.3.2 clients** are supported: the tool profile is read correctly from 2.3.2's sources (its `read` description and integer fields), so a 2.3.2 client's own tools, `read` included, pass unchanged.
- Streamed tool calls whose later fragments carry `"name": null` are accepted, as the OpenAI-compatible format allows.

### Updates

- **Windows:** an update is confirmed only once the new version's dashboard has drawn itself, and only for the executable it installed. The previous executable kept for rollback is no longer removed by another copy of Polygate starting in the same folder.
- **Windows:** the app's copy in `%LOCALAPPDATA%\Polygate\app` records every file it holds. A copy that lost one is made again instead of being chosen on every start.
- **Linux:** a failed update rolls back at any step after the new release is switched in, not only when the service fails to start.
- **Linux:** from this release on, `sudo polygate update` hands the update to the new release's own installer after verifying the download, so improvements to updating apply to the update that brings them.
- Settings that cannot be opened and cannot be set aside now stop the start with a clear message, instead of being replaced by defaults.

### Dashboard

- Totals, the hourly chart and the comparison with the previous day come from hourly counters that keep counting past the detailed log's limit. On upgrade they are filled once from the requests already recorded, so the Overview does not start from zero.
- The last 24 hours mean exactly that for every figure on the Overview.

### Routing

- A relay or route that is resting after failures is skipped when a new request picks its route.
- Surfshark: locations Surfshark no longer offers leave your chosen locations when you press **Update servers**, so **Connect** is not blocked by them.
- Surfshark and Psiphon: a location's OpenCode Free and Kilo Free states are kept apart, and a check for one no longer clears the other. Kilo limits on the first six locations no longer pause Kilo while another location is still free.
- Which service a request is for follows the provider you configured, not only the address it is sent to.
- A provider's only route, while paused, can no longer be deleted (that would have sent its requests through the main route).
- An MCP server sent through a proxy you chose stays on it: when that proxy is switched off, its requests are refused instead of going out directly.
- Z.ai respects **Direct** being switched off.
- Addresses such as `[::ffff:192.168.1.10]` are recognised as local in every written form.

### Agent and models

- A conversation opens even when Polygate is still recording its file changes; the changes show a separate notice.
- Undo recovery restores a file whose content already matches but whose permissions do not.
- Skills dropped into Agent settings before the skill list has loaded are no longer accepted (they could have replaced the existing skills on save).
- Z.ai token limits count what the model actually receives, consistently for reserving, stopping and settling a request, and usage is recorded against the route and model each attempt used.
- A model that refuses one image format (for example TIFF) is no longer marked as unable to see images.
- A model that refuses images gets the conversation with each image replaced by a short note, so one picture no longer breaks every later message of a session.

### Playground

- With one pane, a prompt is added to that pane only. Turning **Compare** on later no longer sends earlier prompts to the second model.

### Upgrading

**Windows:** open **Settings > Updates > Update & restart**, or download `Polygate-0.6.7-Windows-x64.exe` and use it in place of the old executable. The app remains unsigned.

**Linux service users on 0.6.6:**

```bash
sudo polygate update
```

0.6.6's installer keeps the active release and its rollback target, so this is safe. Starting from 0.6.7, updates are finished by the new release's own installer. Users still on **0.6.5** should follow the archive steps in the [0.6.6 notes](https://github.com/B3hnamR/Polygate/releases/tag/v0.6.6) once.

Verify each download against its accompanying `.sha256` file.

**Validation:** TypeScript checking and the full Bun 1.4.4 suite on Windows: 1,272 passed, 0 failed, 24 skipped (Linux-only and environment-specific cases). OpenCode Free was checked live over a direct connection: the route test, streamed and non-streamed answers from DeepSeek and Nemotron, and a tool call. A packaged Windows update from 0.6.6 to 0.6.7 and a Linux update on a real server were not run before release.
