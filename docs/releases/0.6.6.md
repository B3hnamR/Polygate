## Polygate 0.6.6

Surfshark joins the public release, alongside fixes for updates, Agent file history, routing, streaming and the dashboard. Updating is recommended.

### Surfshark

Use **your existing Surfshark subscription** as a gateway route. In your Surfshark account, open **VPN > Manual setup > Desktop or mobile > WireGuard** and obtain a key pair. In Polygate, open **Routing > Surfshark**, save the pair, press **Update servers**, choose and **Save locations**, then **Connect**. Select **Make it the route in use**, or assign it to a supported provider in Routing.

- Each location has its own tunnel. Choose **Take turns** or **Stay on one location**, see connection and exit status, and reconnect a location when needed.
- Used-up exits can be skipped separately for OpenCode Free and Kilo Free. Shared addresses may already be limited; reconnecting does not guarantee a different address or more allowance.
- These tunnels carry only gateway requests. They do not add a system network adapter or change system routes, DNS or firewall rules, and are not a system-wide VPN or kill switch. Fallback follows your routing policy.
- Requires **outbound UDP 51820**, DNS and HTTPS access to the server list. The bundled helper is **wireproxy 1.1.3 (ISC)**, for Windows x64 and Linux amd64/arm64.

No Surfshark accounts or keys are bundled. Polygate is not an official Surfshark app and is not affiliated with Surfshark.

### Safer updates

- **Windows:** portable-app cleanup is restricted to validated Polygate cache copies. The incoming app also handles the restart flag inherited from older updaters, including 0.6.5, rather than treating a temporary extraction as a persistent copy.
- **Linux:** cleanup keeps the active release and its rollback target, including repeated installs and installs of an older version, instead of relying on directory dates.
- Backup restore adds validation before applying settings. Relay deployment stops when it cannot establish whether a name is available, with more careful cancellation and cleanup handling.

### Agent

- Turn changes are captured before slower history lookups, with pending records retained for retry. Later edits are not used to reconstruct an earlier turn's saved file contents.
- Stronger checks around overlapping project folders, Undo, terminals and revoked folder trust. Cancelling work does not wait for optional turn-history lookups.
- Folder backups remain opt-in. Turning them off does not start storing full post-turn file copies.
- Drafts and edits made while a save or first message is in flight are preserved; pending questions are handled more consistently.

### Routing/protocol

- More careful used-up-exit confirmation, including checking the selected WARP tunnel rather than another tunnel. Inconclusive provider failures are not treated as proof that an exit has exhausted its allowance.
- Proxy-pool testing no longer falls back to an arbitrary paid provider. Safer proxy imports avoid silently downgrading explicit HTTPS proxy URLs, preserve SOCKS4a remote DNS, and bound downloaded list size.
- Fixes for Responses images and parallel tool-call history, output-token limits, and Anthropic reasoning/text/tool stream ordering.
- Streaming waits for slow clients and reports upstream errors instead of accepting an empty answer as success. Free-provider tool calls are checked against the tools the client actually offered.

### MCP/UI

- MCP rechecks access after connection setup, including changed keys, server access and disabled tools. Remote HTTP/SSE transport edits now take effect.
- Stronger internal gateway authentication and password-change throttling.
- Fixes for rapid MCP tool toggles, backup-file selection races, editor saves and keyboard focus in dialogs. HTTPS shutdown and rollback handling are also more careful about pending work.

### Upgrading

**Windows:** in 0.4.2 or later, open **Settings > Updates > Update & restart**, or download `Polygate-0.6.6-Windows-x64.exe` from the public release and use it in place of the old executable. Finish active work and back up your settings first. The app remains unsigned. The incoming-update fix covers the older updater's restart flag in source and focused tests; a native packaged 0.6.5-to-0.6.6 upgrade has not yet been verified.

**Linux service users:** connect to your server and run:

```bash
sudo polygate update
```

Verify each download against its accompanying `.sha256` file. Surfshark supports Linux arm64; Psiphon still does not, because upstream publishes no Linux arm64 client.

**Validation:** TypeScript checking and the full Bun 1.4.4 suite passed in an isolated Linux environment: 1,236 passed, zero failed, and eight Windows-native cases skipped. Native Windows, browser, and release-packaging checks run separately in the release workflow. These results do not establish a live Surfshark connection or a native packaged upgrade from 0.6.5.
